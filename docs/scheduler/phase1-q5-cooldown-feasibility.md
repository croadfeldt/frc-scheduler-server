## What Q5 asks

> *Does varying cooldown unlock measurably better other metrics
> (par_quad, opp_quad)? Are there fixture shapes where reducing
> cooldown by 1 unlocks a meaningful quality improvement? Is cooldown
> ever over-constraining?*

This first cut answers the *feasibility* sub-question — for which
`(n, MPT, cooldown)` combinations is there *any* valid schedule?
That's prerequisite to asking whether varying cooldown helps quality.

---

## The feasibility condition

For a fixture `(n, MPT, cooldown, tpa)` with `M` total matches:

A team plays MPT matches at positions `p_1 < p_2 < ... < p_MPT` in
[0, M-1]. Cooldown requires `p_{k+1} ≥ p_k + cooldown`. So the minimum
span across all plays is `(MPT - 1) × cooldown`, and that span must
fit within M - 1.

Solving for cooldown:

```
cooldown_max = floor((M - 1) / (MPT - 1))
```

where `M = ceil(n × MPT / (2 × tpa))`. For surrogate-free fixtures,
`M = n × MPT / (2 × tpa)` exactly; with surrogates, M is the ceiling.

> ⚠ **The formula gives a NECESSARY but not always SUFFICIENT
> condition for feasibility.**
>
> At the cooldown_max boundary, the number of distinct play patterns
> yielding exactly MPT plays may be smaller than n_teams, forcing
> infeasibility despite span fitting. Surfaced empirically 2026-05-12
> via CP-SAT during F1 work:
>
> **Example: 16t × 6MPT × cd=3.** Formula says cooldown_max=3 OK. But
> at cd=3 with M=16 and MPT=6, the only play pattern yielding 6 plays
> in 16 slots is `[0, 3, 6, 9, 12, 15]` — forced exact spacing.
> Patterns starting at index 1 or 2 yield only 5 plays before running
> out of slots. All 16 teams would need the same pattern, but a match
> holds only 6 slots. **CP-SAT correctly reports INFEASIBLE.**
>
> **Mitigation:** treat the formula as a screening check. For boundary
> cases (cooldown exactly at cooldown_max), additional verification
> via CP-SAT or careful combinatorics is needed. Most fixtures
> comfortably below cooldown_max are unaffected; only boundary cases
> need this care. See `phase1-f1-cpsat-refinement.md` for the full
> derivation of the counter-example.

## Findings

**F5-1. No infeasibility in the FRC-common space at typical
cooldown.** Every fixture in the table above is feasible at the
typical cooldown observed for events of that size. The FRC manual's
small-event back-to-back exception (§10.6.6) correctly handles the
genuinely-tight cases (n≤8 with high MPT) where cooldown=1 is the
only feasible choice.

**F5-2. Most fixtures have substantial cooldown headroom.** For 36t ×
7MPT (typical state-level event), cooldown_max = 6 while the typical
cooldown is 3. The schedule could theoretically use up to 6 matches
between a team's plays. **Implication for Q5's quality
sub-question:** there's room to investigate whether increasing
cooldown beyond the typical default improves pairing quality. Smaller
solution space might force the optimizer toward tighter pairing
distributions; this is empirically testable.

**F5-3. Small fixtures (n ≤ 8) have effectively *no* cooldown
choice.** cooldown_max = 1 means back-to-back matches are mandatory.
This is the §10.6.6 small-event regime and is unavoidable. For these
fixtures, cooldown isn't a tunable lever.

**F5-4. Medium fixtures (16 ≤ n ≤ 24) sit in a tight regime.**
cooldown_max is typically 2-3, the typical default is 2. Only ±1
slack. Quality investigations into varying cooldown for these
fixtures should be measured carefully — the solution space is
genuinely constrained.

**F5-5. Large fixtures (n ≥ 36) have very loose cooldown.**
cooldown_max is typically 6-15 while the typical default is 3-4.
There's ample room to experiment. Whether tightening cooldown
improves pairing quality is open and worth measuring.

## What this means for the rest of Phase 1

**Q5's quality sub-question** ("does varying cooldown unlock better
pairing?") is now testable. The methodology:

1. For each fixture in the existing 16-fixture eval inventory,
   identify cooldown_max from the formula.
2. Run the SA at SA=max-budget × best-of-N at each of:
   - typical cooldown (current default)
   - typical + 1
   - cooldown_max
3. Measure `par_quad`, `opp_quad`, `repeat_partners`, `repeat_opponents`
   at each cooldown.
4. Report whether higher cooldown unlocks measurably better pairing.

**Estimated wall-clock**: ~3-5 hours on Stark. This is a small,
contained measurement and a natural Stark job for the Phase 1 budget
(D2 accepted ~1-2 weeks).

**Q2 connection.** The CP-SAT model already runs into infeasibility
at small fixtures. With this formula, we can pre-screen the (n, MPT,
cooldown) space and only attempt CP-SAT runs on feasible cases. Saves
investigation time.

## Formula reference (for future contributors)

To check feasibility of any fixture:

```python
import math

def cooldown_max(n_teams, matches_per_team, teams_per_alliance=3):
    """Returns the largest cooldown for which a valid schedule exists."""
    if matches_per_team < 2:
        return float('inf')  # 1 play, no gap constraint
    M = math.ceil(n_teams * matches_per_team / (2 * teams_per_alliance))
    return (M - 1) // (matches_per_team - 1)

def is_feasible(n_teams, matches_per_team, cooldown, teams_per_alliance=3):
    return cooldown <= cooldown_max(n_teams, matches_per_team, teams_per_alliance)
```

Should be added to `app/scheduler.py` or `app/frc_compliance.py` once
Q5's full investigation lands and we decide whether to expose
cooldown_max in the UI.
